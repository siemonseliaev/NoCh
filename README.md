# CLI-приложение для анализа зависимостей (Этап 1: Минимальный прототип с конфигурацией)

Минимальное CLI-приложение на Python (версии 3.11 и выше), предназначенное для инициализации, конфигурации и проверки параметров запуска[cite: 16, 18].

## Описание проекта

На данном этапе реализации приложение выполняет следующие задачи[cite: 16]:
1. Загружает параметры конфигурации из файла `config.toml` с использованием встроенного модуля `tomllib`[cite: 16, 18].
2. Проверяет наличие всех обязательных параметров, а также корректность их типов данных[cite: 16, 18].
3. Проводит валидацию значений (проверка на отрицательные числа, допустимые режимы работы)[cite: 16, 18].
4. Выводит список успешно загруженной конфигурации в формате `ключ-значение` при запуске приложения[cite: 15, 18].

---

## Настраиваемые параметры (`config.toml`)

В конфигурационном файле должны быть заданы следующие обязательные параметры[cite: 16]:

| Параметр | Тип | Описание | Допустимые значения / Пример |
| :--- | :--- | :--- | :--- |
| **`package_name`** | `str` | Имя анализируемого пакета | Например: `"serde"` |
| **`repo_url`** | `str` | URL-адрес репозитория или путь к файлу | Например: `"https://github.com/example/repo"` |
| **`repo_mode`** | `str` | Режим работы | `"online"`, `"offline"`, `"test"` |
| **`package_version`** | `str` | Версия анализируемого пакета | Например: `"1.0.200"` |
| **`output_image`** | `str` | Имя файла для сохранения изображения графа | Например: `"output.png"` |
| **`max_depth`** | `int` | Максимальная глубина анализа зависимостей | Целое число `>= 0` |

## Архитектура модуля конфигурации

Основной скрипт реализует следующие ключевые блоки[cite: 16, 18]:
* **`load_config(file_path)`** — загрузка и парсинг TOML-конфигурации с обработкой синтаксических ошибок и отсутствия файла[cite: 16, 18].
* **`validate_config(config)`** — строгая проверка типов данных, обязательных ключей и логических ограничений[cite: 16, 18].
* **`main()`** — точка входа приложения, выводящая загруженные параметры в формате `ключ = значение`[cite: 15, 18].
* Обработка исключений (`FileNotFoundError`, `ValueError`, `KeyError`, `TypeError`) с выводом сообщений об ошибках в `sys.stderr` и завершением работы с кодом `1`[cite: 16, 18].
