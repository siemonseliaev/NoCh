# CLI-приложение для анализа зависимостей (Этап 2: Сбор зависимостей Cargo)

Минимальное CLI-приложение на Python (версии 3.11 и выше), предназначенное для инициализации, конфигурации и сбора прямых зависимостей для пакетного менеджера **Cargo** (экосистема Rust).

## Описание проекта

На данном этапе реализации приложение выполняет следующие задачи:
1. Загружает параметры конфигурации из файла `config.toml` с использованием встроенного модуля `tomllib`.
2. Проверяет наличие всех обязательных параметров, а также корректность их типов данных.
3. Проводит валидацию значений (проверка на отрицательные числа, корректность режимов работы).
4. Осуществляет сбор прямых зависимостей Cargo в зависимости от выбранного режима (`online`, `offline`, `test`).
5. Выводит список успешно загруженной конфигурации и найденных зависимостей либо сообщает об ошибках валидации и выполнения.

---

## Настраиваемые параметры

В конфигурационном файле (`config.toml`) должны быть заданы следующие обязательные параметры:

| Параметр | Тип | Описание | Допустимые значения / Пример |
| :--- | :--- | :--- | :--- |
| **`package_name`** | `str` | Имя анализируемого пакета Cargo | Например: `"serde"` |
| **`repo_url`** | `str` | URL-адрес репозитория или путь к файлу | Например: `"https://github.com/serde-rs/serde"` |
| **`repo_mode`** | `str` | Режим работы для получения зависимостей | `"online"`, `"offline"`, `"test"` |
| **`package_version`** | `str` | Версия анализируемого пакета | Например: `"1.0.197"` |
| **`output_image`** | `str` | Путь/имя результирующего файла изображения | Например: `"graph.png"` |
| **`max_depth`** | `int` | Максимальная глубина анализа зависимостей | Целое число $\ge 0$ |

---

## Архитектура модуля сбора данных

Основной скрипт реализует следующие ключевые блоки:
* **`load_config(file_path)`** — парсинг TOML-конфигурации с обработкой синтаксических ошибок.
* **`validate_config(config)`** — строгая проверка типов данных, обязательных ключей и логических ограничений.
* **`fetch_cargo_dependencies(...)`** — маршрутизатор режимов работы (`test`, `offline`, `online`), вызывающий соответствующий метод получения зависимостей (включая работу с REST API **crates.io**).
* Обработка исключений с выводом понятных сообщений об ошибках в `sys.stderr` и завершением работы с кодом `1`.

# CLI-приложение для анализа зависимостей (Этап 4: Дополнительные операции)

Минимальное CLI-приложение на Python (версии 3.11 и выше), предназначенное для анализа и вывода **обратных зависимостей** пакетов экосистемы Cargo (Rust) и тестовых графов.

## Описание проекта (Этап 4)

На данном этапе реализации приложение расширяет функциональность поиска и анализа графа:
1. Выполняет инверсию построенного транзитивного графа зависимостей (алгоритм обхода из предыдущего этапа).
2. Определяет **обратные зависимости** для заданного пакета (`reverse_target`) — список всех пакетов, которые зависят от указанного.
3. Добавляет новый обязательный параметр `reverse_target` в конфигурационный файл `config.toml` и проводит его валидацию.
4. Выводит полный граф обратных зависимостей в консоль для демонстрации связей между компонентами.

---

## Обновленная таблица параметров (`config.toml`)

К существующим параметрам конфигурации добавляется поле **`reverse_target`**:

| Параметр | Тип | Описание | Пример значения |
| :--- | :--- | :--- | :--- |
| **`package_name`** | `str` | Имя анализируемого пакета или путь к test-файлу | `"test_graph.json"` |
| **`repo_url`** | `str` | URL-адрес репозитория или локальный путь | `"local_test"` |
| **`repo_mode`** | `str` | Режим работы (`"online"`, `"offline"`, `"test"`) | `"test"` |
| **`package_version`** | `str` | Версия анализируемого пакета | `"1.0.0"` |
| **`output_image`** | `str` | Путь к итоговому изображению | `"output.png"` |
| **`max_depth`** | `int` | Максимальная глубина анализа | `3` |
| **`reverse_target`** | `str` | **Пакет для поиска обратных зависимостей** | `"A"` |

---

## Архитектура дополнительных операций

В структуру проекта добавлены следующие функции:
* **`get_reverse_dependencies(graph, root_pkg)`** — принимает прямой граф зависимостей, исключает служебные узлы и перестраивает его в инвертированный граф вида `узел -> [пакеты, зависящие от него]`.
* **`run_stage_four(graph, root_pkg, reverse_target)`** — изолированный модуль этапа 4, отвечающий за поиск зависимостей для целевого пакета `reverse_target` и вывод полного обратного графа.
